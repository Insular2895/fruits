# Données chantier - schema à compléter

## Objectif

Définir les données que Fruits doit capter dès le premier actif pour transformer chaque opération en apprentissage réutilisable.

## Principe

```text
Chaque chantier doit produire un rendement financier et un rendement informationnel.
```

## Données à capter

### Coûts

- budget initial ;
- devis par lot ;
- budget révisé ;
- factures ;
- reste à engager ;
- dépassements ;
- contingence utilisée.

### Délais

- planning initial ;
- dates réelles ;
- retards ;
- causes de retard ;
- impact financier ;
- actions correctives.

### Qualité

- réserves ;
- non-conformités ;
- reprises ;
- photos avant / après ;
- PV de réception ;
- garanties activées.

### Productivité

- temps de pose ;
- nombre d'intervenants ;
- cadence par lot ;
- attentes / temps morts ;
- incidents de coordination.

### Fournisseurs et sous-traitants

- nom ;
- lot ;
- prix ;
- respect planning ;
- qualité ;
- réactivité ;
- incidents ;
- score final.

### ESG / énergie

- DPE initial ;
- DPE cible ;
- matériaux clés ;
- consommation réelle si disponible ;
- déchets ;
- carbone / ACV si pertinente.

## Livrables à créer

- template de draw request ;
- tableau budget prévu vs réel ;
- scorecard sous-traitant ;
- registre incident chantier ;
- template reporting mensuel travaux ;
- dossier photos standardisé.

## Questions à compléter

- Quel outil minimal utiliser au début : Notion, Sheets, Airtable, Power BI ?
- Quelles données sont obligatoires dès le premier deal ?
- Quelles données sont utiles mais trop lourdes au départ ?
- Qui remplit les données : Fruits, MOE, entreprise, AMO ?
